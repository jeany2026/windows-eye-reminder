# EyeRestReminder 智能护眼提醒工具

一款面向 Windows 10 / 11 的轻量护眼提醒小工具：统计**有效屏幕使用时长**，达到设定阈值时弹出休息提醒。  
全程只使用 Windows 自带组件（PowerShell 5.1 + .NET Framework + WPF/WinForms），**不需要安装任何第三方运行库**。

## 二、安装 / 使用 / 卸载

### 安装

1. 双击 `EyeRestReminderSetup.exe`，进入安装向导（**许可协议** → 安装目录 → 安装选项 → 完成）。
2. 安装选项：
   - **开机自动启动**（默认勾选）：写入当前用户 `Run` 键，开机后自动后台运行。
   - **创建桌面快捷方式**（默认勾选）。
   - 完成页可勾选 **立即启动**。
3. 安装目录默认：`D:\EyeRestReminder`（本机没有 D 盘时自动改为 `%LOCALAPPDATA%\Programs\EyeRestReminder`），向导中可自行更改。

### 关于「智能应用控制」拦截（重要）

Windows 11 的**智能应用控制（Smart App Control）**&#x5904;于开启状态时，会阻止**未签名 exe**（弹窗无「仍要运行」按钮）。  
本程序因此做了专门适配：

- **所有常驻入口都不依赖未签名 exe**：开始菜单/桌面快捷方式与开机自启动一律指向系统自带的  
  `powershell.exe`（微软签名）直启主脚本；安装负载中也不打包任何 exe。
- **卸载器 `unins000.exe`** 是安装包自身的副本——若安装包能在该机器上运行，它同样可以运行。
- 如果连安装包本身都被智能应用控制拦截，改用免安装绿色版（见下文）即可，全部入口均为脚本。

### 日常使用

- 程序启动后常驻**系统托盘**，无需任何操作。
- 托盘右键菜单只有**设置** / **退出**两项（带齿轮 / 电源小图标）；双击托盘图标直接打开设置面板。
- 设置面板**已打开时**，再点托盘「设置」会直接**唤起已有窗口**置顶，不会另开一套。
  > 实现：设置面板用**非阻塞 `Window.Show()`** 打开（而非 `ShowDialog()`）。`ShowDialog()` 会开启嵌套模态消息循环接管 UI 线程，导致主循环巡检计时器停摆、重复点击的「打开设置」请求积压，关闭面板后才补弹一次（表现为「两套面板」）。改用 `Show()` 后 UI 循环保持畅通，重复点击即时走「已开 → 唤起」分支；面板自身的状态刷新计时器挂在**窗口 Dispatcher** 上独立派发。
- **设置面板打开时也照常弹出护眼提醒**：弹窗 `Topmost` 会显示在面板之上；面板的状态刷新定时器挂在窗口 Dispatcher 上，弹窗的嵌套模态循环期间仍会派发，面板倒计时不停。
- 鼠标悬停托盘图标会实时显示：`千里目｜计时中｜2/20 分`（当前阶段 + 本轮累计/阈值）。
- 开始菜单快捷方式为**千里目** / **设置（千里目）**，桌面快捷方式为**千里目**；  
  安装目录里的 `启动/停止/打开设置.cmd` 均可直接使用。

## 三、功能规则

### 1. 有效使用场景（只有这两类才计入时长）

| 计入           | 说明                                                        |
| ------------ | --------------------------------------------------------- |
| ✅ 用户输入活动     | 键盘 / 鼠标 / 触摸屏触控 / 手写笔，任一种操作                               |
| ✅ 正在播放带画面的视频 | 通过系统媒体会话（SMTC）识别，并判断是视频而非纯音频。**网页视频（含第三方影视站）有专门兜底**，见下方说明 |

| 不计入         | 说明                                                      |
| ----------- | ------------------------------------------------------- |
| ❌ 纯音频播放     | 音乐、播客、有声书等（按应用白名单 + 媒体元数据判定）                            |
| ❌ 视频会议 / 通话 | 进行中的视频会议、语音通话、视频通话期间：不计入用眼时长，且到达提醒阈值时**不弹窗**（详见下节）      |
| ❌ 锁屏        | 工作站被锁定（`OpenInputDesktop` 检测）                           |
| ❌ 显示器休眠     | 屏幕关闭 / 显示电源状态为关（`GUID_CONSOLE_DISPLAY_STATE` 通知 + 主动查询） |

> **看视频不会跳过提醒（2026-10-15 澄清）**：识别「正在看视频」的唯一目的，是让**视频播放这段时间也算作在用眼**，  
> 从而避免「一直盯着视频、不动键鼠」被空闲判定误判成「人已离开」。累计到阈值后，  
> **看视频时同样会弹出提醒**，与键鼠活动没有任何差别。  
> 真正「不算用眼」的只有**视频会议 / 语音通话 / 视频通话 / 纯音频**这几类。


## 四、技术要点

- **单实例保护**：命名互斥体，重复启动会唤起已有的设置面板而不是再开一个实例。
- **后台监控与 UI 分离**：监控循环运行在独立 PowerShell runspace（MTA），UI 在 STA 线程，
  通过同步哈希表共享状态，互不阻塞。
- **状态文件加锁**：`rest_state.json` 读写走命名互斥体 + 临时文件原子替换，避免异常退出导致 JSON 损坏。
- **异常处理规范**：任何异常都会**先落盘状态再写错误日志**，绝不静默卡死；监控线程若意外退出会自动拉起。
- **超时保护**：时间跳变（休眠恢复、系统时间被调整）单次补时上限 60 秒，避免虚增时长。
- **原生能力降级**：若 P/Invoke 模块加载失败，程序仍可正常运行（媒体识别与锁屏/屏幕检测退化为保守判定），
  并在日志中记录。

## 五、已知限制

- 视频识别优先使用 Windows 系统媒体会话（SMTC）。当 SMTC 不可用（精简系统）或播放器不上报会话时，
  程序**降级为按「窗口标题 / 播放器进程」识别** —— 本地播放器、以及标题中含视频关键词的网页
  （如「在线观看」「第01集」）仍能识别；**标题里看不出是视频的网页**（例如只写片名）可能漏判。
- **漏判的后果要说清**：漏判时长时间看视频、不碰键鼠，会被空闲判定当成「人已离开」而**触发计时清零**
  （已累计的时长会一并清掉，提醒可能因此推迟或不来）—— 不是「按看视频继续计时」，也不是「只是不计数」。
- 需要 Windows 10 及以上；不支持 Windows 7/8。
- 计时结果为软件估算，仅供健康提醒参考，不构成医学建议。
